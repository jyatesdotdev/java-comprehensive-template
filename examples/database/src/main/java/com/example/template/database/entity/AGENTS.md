# AGENTS.md — `database.entity`

Read `examples/database/AGENTS.md` for the persistence patterns.

- JPA entities are mutable by necessity, but restricted: no public setters for
  managed fields (`id`, `version`, timestamps, computed totals). `@Version` for
  optimistic locking; `@PrePersist`/`@PreUpdate` own the timestamps.
- Bidirectional associations are maintained ONLY through helper methods
  (`addItem`/`removeItem` sync both sides and call `recalculateTotal()`) — never
  mutate the collection directly from outside.
- `@Enumerated(EnumType.STRING)` for enums, always — ordinal mapping breaks on reorder
  (a test pins the constant order for exactly this reason).
- Associations are `fetch = LAZY`; eager loading is a query concern
  (`LEFT JOIN FETCH` in the repository), not a mapping concern.
- Every entity change requires a matching Flyway migration (portable DDL:
  `GENERATED BY DEFAULT AS IDENTITY`, no vendor-specific types) and entity tests.
